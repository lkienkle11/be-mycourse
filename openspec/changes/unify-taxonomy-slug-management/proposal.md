## Why

`courses.slug` was reworked (`openspec/changes/rework-course-slug-management`) to support an optional manual slug on create/update, omit-preserves-slug semantics, and collision auto-resolution via `internal/shared/slug`. Taxonomy (`course_levels`/`course_topics`/`course_skills`/`tags`, plus the JSONB tree nodes inside topics/skills) never got the same treatment: today it silently recomputes `slug` from `name` on every write (create AND update), accepts no manual input at all, and has no duplicate-key handling — a raw Postgres error currently leaks through as a generic `400`. Before adding a slug to instructor profiles (a separate, later change), the user asked to first bring every other slug-bearing entity in this backend up to the same standard course now has, so the whole system is consistent. Investigation (`/opsx:explore`, prior session) also found and confirmed a real regression in course's own update-path slug retry: it retries a write inside an already-aborted PostgreSQL transaction, so it never actually resolves a real update-time slug collision — this is fixed here since the new taxonomy retry logic must not repeat the same mistake.

## What Changes

- Course bugfix (implementation-only, no spec change — the existing `specs/course/slug-management/spec.md` already requires update-time conflicts to auto-resolve silently; the code just doesn't do it correctly): `internal/course/infra/repo_instructor.go`'s `applyUpdateSlugWithRetry` retries a write on the same `*gorm.DB` transaction after a duplicate-key error, but Postgres aborts the whole transaction on any statement error — the retry's later iterations always fail with a generic "transaction is aborted" error instead of ever succeeding. Fixed with a new shared `internal/shared/gormx.RetryInSavepoint` helper (SAVEPOINT + RollbackTo), reused by taxonomy's own new retry logic below so the fix isn't duplicated.
- New capability `taxonomy/slug-management`: `course_levels`/`course_topics`/`course_skills`/`tags` create endpoints gain an optional `slug` field (omit/empty → auto-generate from `name`, reusing `utils.SlugifyName` plus a new ASCII-fallback for names that transliterate to non-ASCII, matching course's `course-{suffix}` fallback pattern). Update endpoints gain a new, independent, omittable `slug` field (`internal/shared/validate.Optional[string]`, same PATCH-omit-vs-null distinction already used by course) instead of the current always-recompute-from-name behavior: omitted → slug unchanged even if `name` changes (**BREAKING** — today changing `name` always changes `slug`); explicit null/empty/whitespace → `400`; same value → no-op; new value colliding with another active row → silently auto-resolved via random suffix (mirrors course's *update* behavior, not its create behavior, per explicit product decision). Manual slug conflict on **create** → `409` `SlugConflict=3007` + `recommended_slug` (reuses course's existing error code/contract, no new app error code). Duplicate-key races are now caught and retried (`isTaxonomySlugDuplicateKey`, mirroring `isCourseSlugDuplicateKey`) instead of leaking a raw Postgres error as a generic `400`.
- New capability `taxonomy/tree-slug-management`: tree nodes inside `child_topics`/`children` (topic/skill JSONB) gain the same manual-or-auto + omit-preserves-by-ID semantics per node, instead of every write unconditionally re-deriving every node's slug from its name (today's biggest risk: a metadata-only `PATCH` that never touches the tree still silently re-normalizes every node's slug from the DB-loaded tree). In-tree slug collisions are auto-resolved via suffix (not rejected), consistent with the taxonomy-root update decision above. Existing `TreeNode`/`NormalizeTreeSlugs`/`PrepareTreeForWrite` (read path, responses) are unchanged; this is additive (`TreeNodeInput`, `TreeNodeWrite`, `ResolveTreeForWrite`) for the write path only.
- Two new migrations mirroring course's `000039`/`000040` pattern (ASCII backfill covering soft-deleted rows, then a `CHECK` format constraint) applied to all 4 taxonomy tables.
- Out of scope (explicitly deferred): instructor slug (a separate, later change — the original motivating request), media object keys, `course_outcomes` (has no slug field), OAuth provider strings — none of these are user-facing content slugs needing this treatment (confirmed by direct code inspection during `/opsx:explore`).

## Capabilities

### New Capabilities
- `taxonomy/slug-management`: manual-or-auto slug on create, independent omittable slug on update, conflict handling (409+recommendation on manual create conflict, silent auto-resolve on update conflict), duplicate-key retry, format/never-null-in-DB guarantees — for `course_levels`, `course_topics`, `course_skills`, `tags`.
- `taxonomy/tree-slug-management`: same manual-or-auto + omit-preserves-by-ID semantics for tree nodes inside `child_topics`/`children`, plus in-tree duplicate-slug auto-resolution.

### Modified Capabilities
(none — the course update-retry fix corrects an implementation bug against already-correct spec language in `specs/course/slug-management/spec.md`; no requirement text changes)

## Impact

- **Code**: `internal/course/infra/repo_instructor.go` (bugfix only); new `internal/shared/gormx/retry_savepoint.go`; new `internal/taxonomy/infra/slug.go`; `internal/taxonomy/{domain,application,delivery,infra}/*.go` (DTOs, domain inputs, service create/update flows, repository `Save` signatures); new `internal/shared/taxonomy/tree_write.go`; `internal/shared/taxonomy/{tree_validate.go? (no change), service.go}` cleanup of a redundant double-normalize call found during design.
- **DB**: 2 new migrations (ASCII backfill + `CHECK` format constraint) touching `course_levels`, `course_topics`, `course_skills`, `tags` — no new tables/columns, only a new constraint per table (unique index already correct since migration `000012`).
- **API**: `POST/PATCH /taxonomy/{levels,topics,skills,tags}` and `POST/PATCH /taxonomy/topics/:id`/`skills/:id` (tree-bearing) request bodies gain a `slug` field each; no new routes. Manual-conflict responses on create reuse the existing `409`/`3007`/`recommended_slug` contract.
- **Docs**: `docs/reusable-assets.md`, `docs/modules/taxonomy.md`, `docs/database.md`, `docs/api_swagger.yaml` (+ regenerated `docs/api-dog-import.json`), `docs/curl_api.md`, and any other file found to reference today's "taxonomy always derives slug from name" behavior — full list and exact text in `design.md`.
- **Not impacted**: instructor module, media module, course_outcomes, OAuth — confirmed no slug-like field/behavior to change there.
