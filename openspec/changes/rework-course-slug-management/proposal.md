## Why

`courses.slug` is currently 100% server-derived from `title` (`utils.SlugifyName` in `internal/course/application/service.go:courseTitleAndSlug`), with three concrete defects verified in code: (1) no manual/client-supplied slug is ever accepted on create or update — every `PATCH .../basic-info` silently **overwrites** any prior slug whenever `title` is present, because `title` is a required field on every save; (2) collision handling uses a predictable numeric suffix (`base`, `base-2`, `base-3`, ...) with no retry-on-write-conflict on the update path (only create retries on duplicate-key); (3) `SlugifyName` keeps any Unicode letter after NFD diacritic-stripping, so a title in Chinese/Japanese/Thai/Korean/Russian produces a **non-ASCII** slug today — there is no DB constraint catching this. The user needs instructors to be able to see and pick their own course URL slug (a prerequisite the user is calling "vấn đề số 3" for a follow-up instructor-slug feature), and wants the underlying slug mechanism hardened and shared so it does not have to be re-invented for taxonomy (levels/outcomes/skills), media, and instructor slugs later.

## What Changes

- **BREAKING**: `PATCH /api/v1/courses/:courseId/basic-info` no longer recomputes `slug` from `title` on every save. `slug` becomes its own independent, optional (`*string`) field: omitted → unchanged; explicit `null`/`""`/whitespace-only → `400` validation error; a new value → validated, skipped if identical to the current slug, otherwise checked for conflict.
- `POST /api/v1/courses` gains an optional `slug` field (previously not accepted at all — additive, non-breaking): empty/omitted → auto-generate from `title`; provided → validated and checked for conflict.
- New structured conflict contract on manual-slug conflict at **create** only: `409` with app code `SlugConflict` and `data.recommended_slug` (no more silent auto-suffixing of a user-typed slug); the caller resubmits create with the accepted or a different slug. **Update** never returns this — on update-slug conflict the server resolves it directly with a random suffix and returns the actual final slug in the response body (matches the already-existing `Course.Slug` field on every `CourseDetail` response).
- Replaces the numeric-suffix collision algorithm (`base-2`, `base-3`, ...) with a random lowercase-alphanumeric suffix (`crypto/rand`, 7 chars, 7 attempts, then 8 chars, 7 attempts, escalating) for both auto-generated and manual-conflict slugs.
- Auto-generation from `title` switches from `utils.SlugifyName` to `github.com/gosimple/slug` (new dependency) so non-Latin titles (Chinese/Japanese/Thai/Korean/Russian/Vietnamese) produce a meaningful ASCII transliteration instead of a raw Unicode passthrough; an empty/unusable result falls back to `course-{randomSuffix}`.
- Adds a database `CHECK` constraint on `courses.slug` enforcing the ASCII `^[a-z0-9](?:[a-z0-9-]*[a-z0-9])?$` format (first regex `CHECK` constraint in this codebase's migrations) plus a verification/backfill pass for any pre-existing row that would violate it, applied in a separate prior migration so the `CHECK`-adding migration cannot fail on apply.
- Extracts a new reusable package, `internal/shared/slug`, holding the domain-agnostic primitives (format validation, random-suffix generation, ensure-unique-with-retry against a caller-supplied collision check) so future slug work (taxonomy levels/outcomes/skills, media, instructor) can reuse it without duplicating this logic; course-specific business rules (optional-on-create, required-but-omittable-on-update, recommend-then-confirm on create only) stay in `internal/course`.

## Capabilities

### New Capabilities
- `course/slug-management`: course slug format rules, auto-generation from title, manual slug validation, collision resolution (random suffix with escalating retry), and the create-time recommend/confirm contract vs. update-time auto-resolve contract.

### Modified Capabilities
(none — no capability has been archived to `openspec/specs/` yet in this repository, so there is no existing spec whose requirements this change modifies; `course/slug-management` is a new capability.)

## Impact

- **Code**: `internal/course/domain/{course.go,errors.go}`, `internal/course/application/service.go`, `internal/course/delivery/{dto.go,handler_instructor.go,handler_base.go}`, `internal/course/infra/{repo_helpers.go,repo_instructor.go,repos.go}` — all touched; `internal/course/infra/repo_helpers.go`'s numeric-suffix functions (`ensureUniqueCourseSlug`, `nextFreeCourseSlug`, `courseSlugCandidate`, `courseSlugNumericSuffix`, `isCourseSlugNumericSuffixVariant`) are removed and replaced by calls into the new shared package.
- **New package**: `internal/shared/slug` (validation, random suffix, ensure-unique-with-retry).
- **Shared infra extended, not duplicated**: `internal/shared/errors` (new `SlugConflict` app code + message), `internal/shared/response` (no change — its existing `data any` parameter already carries `recommended_slug`). Two items from an earlier draft of this proposal were reconsidered during design and are explicitly NOT done: a new `internal/shared/utils.GenerateRandomAlphaNumeric` (the random-suffix generator instead lives inside the new `internal/shared/slug` package itself, next to the code that uses it) and a new `course_slug` custom validator tag in `internal/shared/validate` (redundant with — and briefly buggy alongside — the direct `sharedslug.ValidateManualFormat` call already made in Go code; see `design.md` D2 for the full reasoning).
- **Database**: 2 new migrations — a backfill/verification migration for any existing non-ASCII/invalid `courses.slug` row, then a migration adding the regex `CHECK` constraint; no new table, no new column (`slug` already exists as `NOT NULL`).
- **Dependency**: adds `github.com/gosimple/slug` to `go.mod`.
- **Tests**: new/updated unit tests in `internal/course/infra` and `internal/shared/slug`; existing tests referencing the numeric-suffix behavior (`repo_helpers_test.go` or equivalent, if present) need updating to the new random-suffix behavior.
- **Docs**: `docs/modules/course.md`, `docs/curl_api.md`, `docs/api_swagger.yaml` (+ regenerated Apidog/Postman import via `ruby generate-apidog-postman.rb`), `docs/database.md` (new `### courses` column table — none existed before), `docs/return_types.md`, `docs/reusable-assets.md`, `docs/router.md`, `docs/security-public-seo-notes.md` — exact literal before/after text for every passage in `design.md`'s "Documentation updates" (Doc-1 through Doc-9), from a live full-text audit of every file that currently mentions "slug". Confirmed unaffected, no edit: `docs/patterns.md`, `docs/modules.md`, `docs/modules/taxonomy.md` (all taxonomy-scoped or generic).
- **Out of scope for this change**: instructor slug, taxonomy/media/level/outcome slugs (explicitly deferred by the user to follow-up work once this shared mechanism exists), course-slug history/redirect table (optional per the user's own spec, tracked as a follow-up), and all frontend work.
